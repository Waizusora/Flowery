# Audio Engine

## Streaming pipeline

`SAF URI → ParcelFileDescriptor → Symphonia → Rubato (when required) → 31-band EQ → bounded PCM ring → AAudio`

`FloweryPlayer.kt` coordinates the worker. `native/src/streaming.rs` implements incremental Symphonia decoding, Rubato resampling, EQ and format-level seeking. `app/src/main/cpp/aaudio_output.cpp` owns AAudio and the PCM ring buffer.

## Decode and resampling

Symphonia probes the selected document and decodes the default audio track packet by packet. The streaming path retains pending samples rather than assembling the entire decoded track in one PCM array. Mono and stereo are supported by the current output path. Scanner extension recognition does not guarantee that every corresponding codec can be decoded.

Rubato 5 uses a fixed-ratio synchronous FFT resampler. Its instance and filter history persist across chunks. When source and output sample rates match, conversion is bypassed. USB output rates are selected using Android-reported device information where available, then validated by attempting to open AAudio. This is not exhaustive USB Audio Class capability enumeration.

## 31-band ISO equalizer

The band centers are 20, 25, 31.5, 40, 50, 63, 80, 100, 125, 160, 200, 250, 315, 400, 500, 630, 800, 1000, 1250, 1600, 2000, 2500, 3150, 4000, 5000, 6300, 8000, 10000, 12500, 16000 and 20000 Hz. Each band uses a peaking biquad with gain constrained to -12 dB through +12 dB. Filter state is retained per channel and band across chunks. Runtime gain updates replace coefficients without clearing filter history.

Native tests check chunk-boundary continuity and coefficient finiteness. The project maintainer has also confirmed that the equalizer works in device testing. The Settings → Audio → Information Audio page describes the decode/resample/EQ/output path and displays the current playback status; it does not currently expose per-stage timing or live DSP meters.

## Ring buffer and callback

The configured ring capacity is 16,384 frames. The worker decodes chunks up to 2,048 frames and targets a 4,096-frame low-water mark. The AAudio callback copies available interleaved float frames, applies output gain, clamps samples, fills underruns with silence, and stops after EOF and queue drain. It does not perform file I/O, decoding, resampling, dynamic allocation, or mutex locking. A flush epoch invalidates stale frames after a seek.

AAudio exclusive sharing is requested first; shared mode is attempted if exclusive opening fails. Shared mode may be mixed or resampled by Android.

## Seeking

Seeking flushes the output ring, performs a format-level Symphonia seek, resets decoder and DSP state, reconfigures the resampler, retains decoder preroll where needed to rebuild Rubato history, and discards output before the requested presentation timestamp. Playback paused/playing state is preserved.

## Output volume policy

Speaker, wired AUX/headphones, and Bluetooth use Android's `STREAM_MUSIC` volume. Flowery reads the current system volume when the UI starts and writes slider changes back to that stream; Android remains responsible for device-specific safe-listening limits and any system warning/confirmation UI. Flowery does not impose a fixed 67% ceiling, because safe-volume thresholds and user override behavior are controlled by Android and may vary by device and region.

USB output uses a separate software gain preference keyed to the selected Android USB output identity. A newly encountered DAC defaults to 20%; subsequent slider changes are saved per key. This is software gain in the current float PCM callback, not physical DAC hardware volume control. The current implementation cannot detect whether a DAC exposes physical volume buttons or map those controls to the application.

## USB DAC discovery and permission

`UsbDacController.kt` enumerates attached USB devices and identifies interfaces declared as USB Audio Class streaming interfaces. The USB icon requests Android USB host permission for the single detected audio device; Android presents the permission prompt and the Activity receives the result through a package-scoped broadcast. The KT Micro KT-384/32 HIFI reference device is identified by the user-supplied USB IDs VID `0x31B2` and PID `0x0111`. This ID match identifies the model reported by the device; it does not establish its advertised PCM formats or prove an active audio route. The additional string `LINUX 55` supplied with the device listing is not interpreted as a USB audio capability because its descriptor field is unknown. After permission is granted, Flowery opens the device temporarily and parses the raw descriptor block. The report lists streaming alternate settings, isochronous endpoints, UAC protocol, and any statically advertised UAC1 PCM channels, subslot sizes, bit resolutions, and sample rates. `UsbDacPlaybackProfile` additionally identifies stereo UAC2 OUT isochronous alternate settings by interface, alternate number, channel count, PCM subslot/bit resolution, endpoint address, packet capacity, service interval, and synchronization type. `UsbDacController.openExclusivePlaybackSession()` now opens the Android USB file descriptor with native libusb, claims the selected interface, negotiates the UAC2 clock with SET_CUR and verifies it with GET_CUR, then selects the matching alternate setting. `UsbDacSession.writePcm()` accepts packed signed integer little-endian PCM and submits asynchronous libusb isochronous transfers in service-interval-sized packets. The native PCM staging queue retains incomplete service intervals across writes and is bounded to two seconds of PCM. Each Android USBFS isochronous URB is capped at 128 service-interval packets. For each direct USB write, Flowery prepares the available PCM as multiple bounded URBs and submits the batch before waiting for completions, allowing the host controller to schedule consecutive service intervals without a per-URB submit/wait gap. Direct USB playback uses 32,768-frame decode blocks to amortize JNI and scheduling overhead; the regular AAudio path retains its 8,192-frame decode blocks. The direct decoded-PCM path records the audio duration, transport duration, and transport-to-realtime ratio for each write. Transfer diagnostics are captured before freeing the libusb transfer object. For the user-tested KT Micro descriptor, the playback candidates are on interface 2, endpoint `0x04 OUT`, with 16-, 24-, and 32-bit alternate settings. This descriptor-derived profile selection is not a streaming transport and does not establish a supported sample-rate list. UAC2 clock-source sampling-frequency RANGE requests are queried from advertised clock-source entities when the device accepts the standard class/interface request. A failed or unsupported request is reported as unavailable; rates are never guessed from the product label. UAC1 continuous sample-rate ranges are also reported. The connection is closed after inspection. If multiple USB audio devices are connected, the UI asks the user to disconnect the unselected devices rather than silently choosing one.

When the user enables USB exclusive mode for the reference KT Micro device, `FloweryPlayer` selects a dedicated direct path for supported RIFF/WAVE integer PCM files. `WavPcmSource` reads the original stereo PCM16/24/32 sample bytes without decoding, scaling, resampling, or EQ. The player requests the source sample rate, opens the native libusb session, claims interface 2, negotiates the linked UAC2 clock with SET_CUR and verifies it with GET_CUR, selects the matching alternate setting, then submits isochronous OUT packets to endpoint `0x04`. Playback is reported active only after the first successful transfer; the USB icon turns blue at that point. Seek, pause and resume are handled by the direct-path worker. Unsupported formats, channel layouts, bit depths, sample rates or failed USB negotiation stop with an explanatory playback error rather than silently falling back to DSP.

When USB exclusive mode is enabled for a supported non-WAV source, `FloweryPlayer` uses Symphonia to decode stereo audio to float PCM, applies the configured DSP, quantizes the result to packed signed 24-bit PCM, and sends it through the same native libusb UAC2 transport. This bypasses Android's audio mixer but is not source-bit-perfect playback. The transport records the selected endpoint's packet capacity, service interval, and synchronization type. On an isochronous transfer failure, the native error includes the transfer status and the first failed packet's status and actual/requested lengths where available, together with the endpoint, service interval, and sample rate. These diagnostics identify the failing USB layer; they do not by themselves establish a hardware-verified bit-perfect result.

The direct PCM path keeps digital volume at unity because software gain would alter the samples. Use the DAC's physical volume control. Flowery does not yet detect hardware-volume capability or map physical volume keys. The normal Symphonia → Rubato → EQ → AAudio path remains unchanged when USB exclusive mode is disabled.

## Output limitations

The current end-to-end direct path is deliberately limited to stereo RIFF/WAVE integer PCM16/24/32. It does not yet support FLAC, ALAC, AIFF, DSD, floating-point WAV, compressed formats, or multichannel output in USB bit-perfect mode. The native transport has not yet been validated on the physical KT Micro unit with a USB protocol trace or external digital capture. A successful UAC2 clock readback and completed isochronous transfers are necessary runtime checks, but external measurement is still required before making a hardware-verified bit-perfect claim. The normal AAudio path outputs PCM float and can fall back from exclusive to shared mode; it is not bit-perfect. Gapless playback and crossfade are also not implemented.

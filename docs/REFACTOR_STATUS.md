# Architecture Refactor Status

This document records the verified implementation state of the seven architecture workstreams. It distinguishes existing implementation from remaining migration work; a target design is not evidence that a migration is complete.

## Ownership invariants

- Kotlin owns Android framework integration: Activity and Compose lifecycle, Storage Access Framework descriptors and URI grants, USB permission and Android control transfers, output-device discovery, audio focus, MediaSession, notifications, and platform volume.
- Rust owns audio-domain policy and processing: demuxing and decoding, typed source samples, resampling, equalization, PCM and encoded producers, bounded audio queues, UAC descriptor interpretation, playback route eligibility, playback queue policy, playback lifecycle state, and the AAudio backend.
- C++ owns the direct USB transport: libusb context and handles, interface claims, endpoint setup, isochronous transfers, feedback handling, completion/cancellation, and transport teardown.
- Do not add a second decoder, DSP implementation, PCM format policy, or UAC descriptor parser in Kotlin or C++.

## Safe migration order

1. Preserve and extend the Rust-only UAC descriptor parser and its fixtures.
2. Create one registry-backed native session per playback generation; it owns the shared decoder reference, route identity, seek epoch, cancellation, and phase transitions.
3. Bind both direct USB producer types to the native session so a seek invalidates stale pending/queued output through one session epoch and cancellation prevents further decode/publish work. Serialize session seek/cancel/close transitions and join or synchronize producer work before releasing handles.
4. Keep Kotlin responsible for Android USB permissions, SAF descriptor acquisition, output discovery, and libusb session control; C++ remains the transport consumer.
5. Extract Compose destinations independently from the audio migration.
6. Direct USB PCM decode scheduling, AAudio decode scheduling, and encoded packet production now use Rust-owned workers with bounded queues or ring-buffer backpressure. AAudio pause/resume and output teardown are dispatched through the native session command API rather than directly controlled by Kotlin. Encoded packets still cross JNI as a byte array, but Kotlin no longer creates a second payload array: it passes the payload offset/length directly to the C++ writer, which copies only the payload into the bounded transport staging buffer. Next move the AAudio prebuffer/start/monitor scheduler and seek/segment orchestration behind the native session, then move encoded packet draining and transport pacing out of Kotlin and add end-to-end lifecycle/route tests.
7. Require CI and device-level evidence at each milestone.

## Verification notes

A passing JNI declaration check verifies symbol presence and signature consistency only. Registry-backed handles and reference-counted decoder/producer state remove raw decoder/producer/queue pointers from the audited JNI paths. Native unit tests verify software behavior only. CI packaging verifies that Android native libraries and APKs can be built. None of these alone proves a physical DAC accepts every advertised profile or that the DAC output is bit-exact. Hardware claims require external digital capture and, where applicable, USB protocol traces.

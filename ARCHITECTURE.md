# Architecture

Flowery separates the Android application layer, the Rust audio engine, and the native C++ direct-USB transport. Android AAudio output is implemented entirely in `native/src/aaudio.rs` through Rust declarations of the Android NDK C API; there is no AAudio C++ implementation or AAudio CMake target. The only application-owned C++ translation unit, `app/src/main/cpp/usb_audio_jni.cpp`, implements the explicitly retained libusb transport. `MainActivity` provides the Compose UI. `LibraryScanner` traverses user-selected Storage Access Framework trees. `PlaybackService` manages foreground playback, media-session integration, audio focus, and Android service events. `PlaybackCoordinator` is a Kotlin adapter over a Rust-owned playback lifecycle state handle. Rust in `native/src/queue.rs` owns queue index, repeat mode, shuffle state, and next/previous/completion transitions; Kotlin retains the URI and metadata arrays required by Android notifications and media sessions. `FloweryPlayer` manages Android SAF descriptors, output-route selection, volume, worker-thread lifetime, and platform-driven commands, while the playback state and queue policy live in Rust. Rust in `native/src/playback_policy.rs` owns preferred-rate selection, output ring sizing, millisecond-to-frame conversion, and AAudio prebuffer watermarks. For AAudio playback it requests bounded native pump operations; Rust performs each decode/resample/EQ/ring-write step without returning PCM arrays to Kotlin. For direct USB playback, Rust parses and reads WAV integer-PCM data, performs software gain and generic negotiated-PCM conversion for decoded sources, and owns the bounded producer-to-writer PCM queue. Kotlin retains Android USB permission and session lifecycle plus the libusb transport calls. `NativeAudio` declares the JNI boundary.


The native playback API is streaming-oriented. Whole-file PCM decoding and stateless JNI resampling/equalization entry points are not part of the supported interface; Kotlin does not receive or retain an entire decoded track for normal playback.

The streaming audio path opens a SAF document descriptor, decodes packets incrementally with Symphonia, resamples with a persistent Rubato instance when required, applies the native 31-band ISO equalizer, and writes PCM frames directly from Rust into a bounded single-producer/single-consumer ring buffer owned by the Rust AAudio backend. Kotlin controls the native pump cadence and Android lifecycle but no longer copies AAudio PCM chunks through Java FloatArrays. Its native callback consumes frames. It does not perform file I/O, decoding, resampling, allocation, or mutex locking.

The streaming decoder supports mono and stereo. The equalizer requires 31 gains and constrains each band to -12 dB through +12 dB. Resampler and per-channel EQ history persist between chunks. Seeking flushes queued output, performs a format-level seek, resets decoder/DSP state, and discards preroll before playback resumes.

The library uses Storage Access Framework and `DocumentFile`; it does not use MediaStore. Rust owns audio classification, same-directory sidecar matching, CUE/M3U/M3U8/PLS parsing and association, root-confined relative-path resolution, virtual-track creation, CUE time calculations, and catalog deduplication. Kotlin traverses enabled SAF trees, reads playlist text using the configured charset, and maps Rust catalog URI values to Android document models. For metadata, Kotlin passes SAF file descriptors through JNI; Rust stages descriptor contents in the app-private cache for Lofty processing, avoiding full-file JNI byte-array transfers, and edited staged files are streamed back through the SAF output stream. The foreground service maintains `MediaSessionCompat`, handles notification/media-button actions and audio focus, and responds to noisy-route events.

## USB DAC access

`UsbDacController` discovers USB Audio Class streaming interfaces without a model-specific VID/PID whitelist and requests Android USB host permission. Kotlin retains Android USB permission, device connection, and class-specific control transfers; Rust parses UAC descriptors, derives stereo UAC2 OUT profiles, validates PCM valid-bit/subslot layouts, and resolves clock links. Clock RANGE values are queried from the linked UAC2 clock entities, then the selected sample rate is negotiated with SET_CUR and verified with GET_CUR by the C++ libusb transport. Raw descriptors, parsed profiles, clock ranges, VID/PID, and observation history are stored in the local SQLite DAC profile database using a SHA-256 descriptor fingerprint. Standard USB descriptors do not reliably identify physical silicon, so Flowery does not infer chipset identity from product names. `UsbDacController.openFirstCompatiblePlaybackSession()` tries permission-granted DACs and descriptor-derived PCM resolutions, preferring higher valid-bit resolutions when automatic selection is requested. Decoded playback can choose a supported clock rate and configures the Rust decoder/resampler to that rate; source WAV passthrough requires an exact source rate and matching subslot layout. Rust's `native/src/usb_pcm.rs` defines the shared `PcmFormat` contract (sample rate, channels, valid bits, subslot width, signedness, and endianness), and `native/src/streaming.rs` packs decoded samples for the selected format. `native/src/wav_pcm.rs` remains a source adapter for byte-preserving integer WAV playback. Both adapters feed the bounded queue in `native/src/usb_pcm.rs` and the same C++ libusb isochronous transport. The direct transport currently supports stereo UAC2 profiles with 8–32 valid bits and 1–4 byte subslots; UAC1 direct streaming and multichannel output are not implemented.

## Navigation and settings UI

`FloweryNavigation.kt` provides the four-icon navigation surface: Folders, Lyrics, DSP, and Settings. The Folders destination shows configured SAF roots and opens a folder-scoped track list. Playback requests from that list construct the queue from the selected folder's scanned tracks. Removing selected roots removes their app configuration and releases persisted URI permissions; it does not delete source documents.

Lyrics toggles the sidecar LRC presentation in the artwork area. DSP exposes software volume and the 31-band equalizer. Ordinary speaker, wired AUX/headphone, and Bluetooth volume follow Android's `STREAM_MUSIC` volume and its system safe-listening policy. USB output has a separate per-device software gain preference, initialized to 20% for a newly seen output; it applies to the AAudio path and to the decoded direct USB path, while the WAV bit-perfect path keeps digital gain at unity. The AAudio float pipeline does not provide hardware DAC button control or bit-perfect output. The direct USB route supports descriptor-derived UAC2 stereo PCM profiles; the bit-perfect claim is limited to unchanged WAV PCM sample bytes at unity gain with ducking disabled, and has not been hardware-verified. Settings groups audio information, library guidance, appearance, and other application options. The Other section contains battery-optimization access and an About entry. About contains Open Source, Translator, Contributor, and Update pages. The Settings → Audio page contains Information Audio and USB Diagnostics. USB Diagnostics → Record Log is the only diagnostic capture/export workflow; it combines AAudio telemetry, direct USB/libusb events, and descriptor/clock snapshots. Raw descriptor blocks and parsed reports are stored in local SQLite, keyed by VID/PID plus descriptor fingerprint. Standard USB descriptors do not reliably identify silicon, so the database does not assert an unverified chipset model. The settings cards display category icons, and the content remains vertically scrollable. Audio information includes the current playback status and the implemented decode-to-output pipeline; per-stage timing and live DSP meters are not exposed. The Open Source page lists direct application and native dependencies with their declared versions where available. Auto appearance follows Android's system dark-mode setting. Language and translator/contributor credits remain concept pages until localization and confirmed credit records are available.


## Native lyrics parsing

Sidecar LRC timestamp recognition, multi-timestamp expansion, text cleanup, and chronological ordering are implemented in the Rust library. The JNI adapter returns structured JSON; Kotlin maps the result to the UI-facing lyric model and selects the line for the current presentation position. Android document access and lyric presentation remain platform responsibilities.


## Native playlist parsing

CUE, M3U, and PLS text parsing is implemented in Rust and exposed through JNI. Kotlin retains charset decoding, Android Storage Access Framework document resolution, and UI-facing data models. CUE parsing preserves track frame offsets and derives end offsets from the next track that references the same source file.

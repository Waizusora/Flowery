# Architecture

Flowery separates the Android application layer, the Rust audio engine, and the native C++ direct-USB transport. Android AAudio output is implemented entirely in `native/src/aaudio.rs` through Rust declarations of the Android NDK C API; there is no AAudio C++ implementation or AAudio CMake target. The only application-owned C++ translation unit, `app/src/main/cpp/usb_audio_jni.cpp`, implements the explicitly retained libusb transport. `MainActivity` provides the Compose UI. `LibraryScanner` traverses user-selected Storage Access Framework trees. `PlaybackService` manages foreground playback, media-session integration, audio focus, and Android service events; Rust in `native/src/queue.rs` owns queue transition policy for next, previous, completion, shuffle, and repeat. `FloweryPlayer` manages Android SAF descriptors, output-route selection, volume, playback lifecycle, and user-driven seeking. For AAudio playback it requests bounded native pump operations; Rust performs each decode/resample/EQ/ring-write step without returning PCM arrays to Kotlin. For direct USB playback, Rust parses and reads WAV integer-PCM data, performs software gain and packed-24-bit conversion for decoded sources, and owns the bounded producer-to-writer PCM queue. Kotlin retains Android USB permission and session lifecycle plus the libusb transport calls. `NativeAudio` declares the JNI boundary.

The streaming audio path opens a SAF document descriptor, decodes packets incrementally with Symphonia, resamples with a persistent Rubato instance when required, applies the native 31-band ISO equalizer, and writes PCM frames directly from Rust into a bounded single-producer/single-consumer ring buffer owned by the Rust AAudio backend. Kotlin controls the native pump cadence and Android lifecycle but no longer copies AAudio PCM chunks through Java FloatArrays. Its native callback consumes frames. It does not perform file I/O, decoding, resampling, allocation, or mutex locking.

The streaming decoder supports mono and stereo. The equalizer requires 31 gains and constrains each band to -12 dB through +12 dB. Resampler and per-channel EQ history persist between chunks. Seeking flushes queued output, performs a format-level seek, resets decoder/DSP state, and discards preroll before playback resumes.

The library uses Storage Access Framework and `DocumentFile`; it does not use MediaStore. The Rust library owns the supported audio-extension registry and classifies candidate audio files through JNI; Kotlin retains SAF traversal and URI handling. The foreground service maintains `MediaSessionCompat`, handles notification/media-button actions and audio focus, and responds to noisy-route events.

## USB DAC access

`UsbDacController` discovers attached USB Audio Class streaming interfaces and requests Android USB host permission. It recognizes the KT Micro KT-384/32 HIFI reference device using VID `0x31B2` and PID `0x0111`; this is identification only and does not imply that direct USB streaming or bit-perfect output is active. The permission result is shown to the user. After permission is granted, the controller reads and parses the raw USB descriptors and displays discovered streaming alternate settings and endpoint/format information. `UsbDacPlaybackProfile` derives stereo UAC2 OUT isochronous playback candidates and filters them by PCM resolution. `UsbDacController.openExclusivePlaybackSession()` opens the Android-authorized file descriptor with libusb, claims the selected streaming interface, writes the requested UAC2 clock frequency and reads it back, then selects the alternate setting. `UsbDacSession` exposes bounded integer-PCM writes through native isochronous transfers. `FloweryPlayer` selects this direct path when USB exclusive mode is enabled: Rust's `native/src/wav_pcm.rs` parses and reads supported WAV integer PCM directly, while other supported sources are decoded by Symphonia and packed as signed 24-bit PCM in `native/src/streaming.rs`. Both direct paths use the bounded native block queue in `native/src/usb_pcm.rs`. Kotlin coordinates the Android USB session and forwards PCM blocks to the retained libusb transport. The decoded path is not source-bit-perfect. Hardware-verified bit-perfect playback and physical DAC button-volume integration are not claimed.

## Navigation and settings UI

`FloweryNavigation.kt` provides the four-icon navigation surface: Folders, Lyrics, DSP, and Settings. The Folders destination shows configured SAF roots and opens a folder-scoped track list. Playback requests from that list construct the queue from the selected folder's scanned tracks. Removing selected roots removes their app configuration and releases persisted URI permissions; it does not delete source documents.

Lyrics toggles the sidecar LRC presentation in the artwork area. DSP exposes software volume and the 31-band equalizer. Ordinary speaker, wired AUX/headphone, and Bluetooth volume follow Android's `STREAM_MUSIC` volume and its system safe-listening policy. USB output has a separate per-device software gain preference, initialized to 20% for a newly seen output; it applies to the AAudio path and to the decoded direct USB path, while the WAV bit-perfect path keeps digital gain at unity. The current AAudio float pipeline does not provide hardware DAC button control or a bit-perfect USB transport. Settings groups audio information, library guidance, appearance, and other application options. The Other section contains battery-optimization access and an About entry. About contains Open Source, Translator, Contributor, and Update pages. The settings cards display category icons, and the content remains vertically scrollable. Audio information includes the current playback status and the implemented decode-to-output pipeline; per-stage timing and live DSP meters are not exposed. The Open Source page lists direct application and native dependencies with their declared versions where available. Auto appearance follows Android's system dark-mode setting. Language and translator/contributor credits remain concept pages until localization and confirmed credit records are available.


## Native lyrics parsing

Sidecar LRC timestamp recognition, multi-timestamp expansion, text cleanup, and chronological ordering are implemented in the Rust library. The JNI adapter returns structured JSON; Kotlin maps the result to the UI-facing lyric model and selects the line for the current presentation position. Android document access and lyric presentation remain platform responsibilities.


## Native playlist parsing

CUE, M3U, and PLS text parsing is implemented in Rust and exposed through JNI. Kotlin retains charset decoding, Android Storage Access Framework document resolution, and UI-facing data models. CUE parsing preserves track frame offsets and derives end offsets from the next track that references the same source file.
